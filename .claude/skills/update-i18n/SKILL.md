# Update i18n — karmanto.com

Angular XLF i18n, `sourceLocale: en`. All files live in `apps/site/src/locale/` and are committed:

| File              | Role                                          | Target |
| ----------------- | --------------------------------------------- | ------ |
| `messages.xlf`    | source, generated by `extract-i18n`           | —      |
| `messages.ru.xlf` | translation, `target-language="ru"`           | ru     |
| `messages.es.xlf` | translation, `target-language="es"`           | es     |

The build fails on any missing translation (`i18nMissingTranslation: error`), so this skill must leave both files
complete.

## Step 1: Extract

```sh
yarn nx extract-i18n site
```

Extraction compiles the app: if it fails, fix the compile error first (it is a real build error, not an i18n problem).

## Step 2: Compare IDs

```sh
python3 - <<'EOF'
import re
ids = lambda f: re.findall(r'<trans-unit id="([^"]+)"', open(f'apps/site/src/locale/{f}').read())
src = ids('messages.xlf')
for loc in ('ru', 'es'):
    tr = ids(f'messages.{loc}.xlf')
    print(loc, 'new:', [i for i in src if i not in tr], 'stale:', [i for i in tr if i not in src])
EOF
```

- **New** — `id` is in `messages.xlf` but not in the translation file.
- **Stale** — `id` is in the translation file but not in `messages.xlf`.

## Step 3: Add new units

Copy the full `<trans-unit>` block from `messages.xlf` into the translation file (before `</body>`, keep the
indentation) and add `<target>` right after `<source>`, in the existing format (no `state` attribute):

```xml
<trans-unit id="4976405609760757335" datatype="html">
  <source>This page is coming soon.</source>
  <target>Эта страница скоро появится.</target>
  <context-group purpose="location">…</context-group>
  <note priority="1" from="description">…</note>
  <note priority="1" from="meaning">…</note>
</trans-unit>
```

Translation rules:

- Use the `meaning` and `description` notes as context; translate naturally, not word-for-word. Short UI labels
  stay short.
- Keep placeholders (`<x id="…" …/>`) and leading/trailing whitespace of the source intact.
- Keep brand and product names as in the source (the brand is going to change — never translate or transliterate it).
- Never write legal texts (privacy, terms, consent): if a unit is legal content, stop and ask the owner.
- The `id` depends on text + meaning: changing either creates a new unit, so the old translation shows up as stale.
  Reuse it for the new unit when the change is cosmetic, otherwise translate again.

## Step 4: Remove stale units

Remove the whole `<trans-unit>…</trans-unit>` block of each stale unit.

## Step 5: Verify

```sh
yarn nx build site
```

Re-run step 2: new = 0 and stale = 0 for both locales. The build must pass (it validates the XML and every target).

## Step 6: Report

Per locale: units **added** (source → translation), units **removed**, total unit count.
