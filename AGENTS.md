# Инструкции для агентов — karmanto.com

Сайт мобильного приложения Karmanto (карточки для запоминания слов, iOS и Android): маркетинговая страница,
юридические документы, поддержка, удаление аккаунта, форма обратной связи. Чистая статика: Angular SSG → свой
сервер (nginx, rsync из CI на push в `main`; настройка — `docs/hosting.md`). Полный план — `docs/plan.md`.

Образец — репозиторий `isomantika.com`: архитектура, страницы и бизнес-логика переносятся из него почти один в один,
меняются бренд, цвета, шрифт и тексты. Решения образца (`docs/decisions.md` образца) действуют, если в
`docs/decisions.md` этого репозитория не сказано иначе.

Общие инструкции для любого агента. Источник истины — этот файл и документы репозитория.
Адаптеры инструментов ссылаются на общие правила и сценарии, не дублируя их.

## Начало работы

1. Прочитай [прогресс](docs/progress.md), текущую задачу в [плане](docs/plan.md)
   и связанные [решения](docs/decisions.md).
2. Всегда прочитай [правила Git](docs/agents/rules/git.md).
3. До работы с файлами прочитай все применимые правила ниже. Области пересекаются;
   не рассчитывай на автоматическую загрузку правил конкретным инструментом.

| Область                                                                              | Правила                                                        |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `apps/**`, `libs/**`, `tools/**`, конфигурация сборки и зависимостей, `brandbook/**` | [Angular, Nx и устройство сайта](docs/agents/rules/angular.md) |
| Тексты шаблонов, `$localize`, `apps/site/src/locale/**`, `content/**`                | [Переводы](docs/agents/rules/i18n.md)                          |

## Где хранить знания о проекте

Общий контекст живёт в репозитории, чтобы продолжать работу любым агентом и с другого устройства.

- Общие договорённости → `AGENTS.md`; правила областей → `docs/agents/rules/`.
- Решения и отклонения от плана → `docs/decisions.md`: новая запись сверху с датой, решением и причиной.
  Отличай согласованное от предложенного.
- Прогресс → `docs/progress.md`: `[~]` / `[x]`, при частичном завершении — что осталось.
  Для работы вне плана не отмечай несвязанные задачи выполненными.
- Повторяемые сценарии → `docs/agents/workflows/`.
- Просьба «запомнить» → [сохранение знаний](docs/agents/workflows/remember.md): обнови существующее правило вместо дубля.

Личная память агента и история чата не заменяют документы проекта. Локальные настройки и разрешения
остаются в конфигурации инструмента; `.claude/settings.local.json` и `CLAUDE.local.md` исключены из Git.
Не сохраняй секреты и абсолютные локальные пути в общих инструкциях.

## Сценарии

Работают по обычной просьбе, без обязательных slash-команд или поддержки скиллов:

- «Следующая задача» → [сценарий](docs/agents/workflows/next-task.md).
- «Запомни» → [сценарий](docs/agents/workflows/remember.md).
- «Обнови переводы» или изменение строк i18n → [сценарий](docs/agents/workflows/update-i18n.md).
- «Обнови вендоры» → [сценарий](docs/agents/workflows/update-vendors.md).

Скиллы Claude `update-i18n` и `update-vendors` — адаптеры к этим сценариям.
Внешний справочник Angular и порядок его чтения описаны в правилах Angular.

## Команды

```sh
yarn start           # nx serve site — dev-сервер, только en
yarn build           # nx build site — все локали + 404.html
yarn serve           # nx serve-static site — собранная статика (404 — общий `404.html`)
yarn extract-i18n    # nx extract-i18n site
yarn test            # unit-тесты всех проектов
yarn lint            # линт всех проектов с --fix
yarn e2e             # Playwright по статике
yarn check           # lint test build e2e — задача готова, когда зелёный
yarn affected        # то же для затронутых проектов
yarn format          # Prettier
```

## Правила работы

- **Перед выполнением любой задачи — grill me.** Сначала расспроси владельца о неочевидных решениях
  (поведение, UX, тексты, крайние случаи), предложи варианты с рекомендацией; код — только после ответов.
  То, что уже решено в образце и не меняется в плане, не спрашивай — переноси.
  Уже согласованные в текущей беседе решения повторно не спрашивай.
- Для изменений кода задача готова, когда `yarn check` (lint, test, build, e2e) зелёный.
  Для изменений только документации и инструкций проверь ссылки, согласованность правил, форматирование
  и `git diff --check`; запуск сборки и e2e не нужен. Статус — в `docs/progress.md`.
- Принятые решения и отступления от плана — в `docs/decisions.md`.
- `README.md` — витрина на GitHub: сверху на английском дублирует тексты главной, ниже — раздел для разработчиков.
  Меняются тексты главной — обновлять README в той же задаче.
- На сайте не упоминаются цена, Pro и лимиты приложения.
- Не расширять объём задачи: то, что в плане помечено «Не входит», без явной просьбы не делаем.
- Юридические тексты (`content/`): черновики пишет агент один раз, в задаче 3, по прямой просьбе владельца. После
  этого — не писать, не генерировать и не править их без явной просьбы, даже опечатки, только сообщить. Никаких
  секретов в репозитории.

В отчёте укажи результат, проведённые проверки и оставшиеся ограничения.
